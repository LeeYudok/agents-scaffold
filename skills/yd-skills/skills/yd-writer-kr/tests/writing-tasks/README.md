# 글쓰기 품질 평가 과제

스킬로 쓴 글이 스킬 없이 쓴 글보다 나은지 재는 과제 12개다(#139).
검사기 테스트는 정한 표현을 잡는지만 본다. 이 과제는 같은 원자료로 쓴 글 두 편을 비교한다.

| 종류 | 과제 | 보는 것 |
|---|---|---|
| 이슈 본문 | `issue-01` ~ `issue-03` | 배경·할 일·판정, 정하지 않은 것을 정한 것처럼 쓰지 않는가 |
| 공지 | `notice-01` ~ `notice-03` | 첫 줄에 결론, 내부 사정을 뺐는가, 500자 이하 |
| 장애 보고 | `incident-01` ~ `incident-03` | 첫 문단에 피해 규모, 추정과 확인을 구별했는가 |
| 회의록 요약 | `minutes-01` ~ `minutes-03` | 결정·할 일·미결을 섞지 않았는가 |

원자료(`materials/`)는 모두 지어낸 내용이다. 실제 고객·장애 자료는 넣지 않는다.

## 돌리는 법

1. 과제마다 지시문을 뽑는다. 지시문에는 원자료와 독자만 있고 채점 기준은 없다.

   ```bash
   python3 <스킬경로>/scripts/score_writing_tasks.py --list
   python3 <스킬경로>/scripts/score_writing_tasks.py --prompt issue-01
   ```

2. 같은 지시문으로 글을 두 번 쓰게 한다. 한 번은 스킬 없이, 한 번은 스킬을 켜고 쓴다.
   결과는 폴더 두 개에 `<과제 id>.md` 로 저장한다. 예: `baseline/issue-01.md`, `skill/issue-01.md`.
3. 기계 채점을 한다.

   ```bash
   python3 <스킬경로>/scripts/score_writing_tasks.py baseline --compare skill
   ```

4. 가린 비교지를 만들어 사람이 고른다. 열쇠 파일은 다 고른 뒤에 연다.

   ```bash
   python3 <스킬경로>/scripts/score_writing_tasks.py --blind baseline skill -o 비교지.md --key 열쇠.json
   ```

## 공정하게 비교하려면

- 두 쪽 모두 같은 모델, 같은 지시문을 쓴다. 지시문에 채점 기준이나 원하는 형식을 덧붙이지 않는다.
- 스킬 없는 쪽은 스킬과 전역 글쓰기 지침이 없는 깨끗한 세션에서 쓴다. 지침이 섞이면 차이가 줄어든다.
- 글을 쓴 쪽에 채점 결과를 보여 주고 다시 쓰게 하지 않는다. 과제에 맞춘 글이 된다.
- 표본이 12개라 한두 과제가 결과를 바꾼다. 과제별 점수와 놓친 항목을 함께 본다.

## 채점 항목

과제마다 항목 하나가 한 점이다. 기준은 `tasks.json` 에 있다.

| 항목 | 뜻 |
|---|---|
| 검사기 오류 0건 | 금지 표현, 명사형 종결, 표기 프로필 위반이 없다 |
| 원문 대조 오류 0건 | 원자료에 없는 날짜·시각·이슈 번호·코드·URL 이 없다 |
| 사실 (`must_have`) | 꼭 들어갈 수치·날짜·담당·단서("추정", "미정")가 있다 |
| 첫머리 (`lead`) | 결론이 제목을 뺀 앞 몇 줄 안에 있다 |
| 절 (`section`) | 그 사실이 맞는 절에 있다. 미결을 결정 절에 쓰면 점수를 잃는다 |
| 금지 (`must_not`) | 내부 사정, 원자료와 다른 단정이 없다 |
| 절 제목, 분량 | 종류별 절이 있고 글자 수 한도를 넘지 않는다 |

검사기 경고는 점수에 넣지 않고 수만 보여 준다.

## 한계

- 채점기는 문자열이 있는지만 본다. 같은 뜻을 다른 말로 쓰면 놓친다. `any` 에 다른 표현을 더해 고친다.
- 점수가 높다고 좋은 글은 아니다. 읽기 쉬운지는 비교지로 사람이 판단한다.
- 절 제목은 `## 결정`, `**결정**`, `결정:` 꼴만 알아본다.

## 과제를 더할 때

1. `materials/<id>.md` 에 원자료를 쓴다. 메모·로그·대화처럼 다듬지 않은 글로 쓴다. 날짜는 `2026-11-20` 이나 `11월 20일` 꼴로 적는다.
2. `tasks.json` 의 `tasks` 에 항목을 더한다. `lead`·`must_have`·`must_not` 을 모두 채운다.
3. `must_have` 의 값은 원자료에 그대로 있어야 한다. 단서처럼 표현이 달라지는 항목만 `"free": true` 를 붙인다.
4. `python3 -m unittest tests/test_writing_tasks.py` 로 형식을 확인한다.
