# yd-visual-brief

## 역할

원자료를 읽고 결재자가 한눈에 이해하는 문서 한 장을 만든다. 읽는 사람은 긴 글보다 그림으로 더 빨리 이해한다. 그래서 장마다 그림이 주인이고 글은 그림을 설명한다.

산출물은 HTML 파일 하나다. 그림은 모두 자료에서 그린 SVG 다. 글 본문은 `yd-writer-kr` 로 쓴다.

## 언제 쓰나

- 사업계획서, 결재 문서, 제안서, 현황 보고처럼 결정을 받아야 하는 문서
- "그림으로", "한눈에", "구성도 넣어서" 처럼 그림을 요구받았을 때

쓰지 않는 경우: 이슈·PR 본문, 공지, 회의록 요약처럼 글만 필요한 문서는 `yd-writer-kr` 를 쓴다.

## 작업 순서

1. 원자료와 독자를 정한다. 원자료 파일 목록과 독자(누가 결재하는가)를 적는다. 원자료에 없는 수치·날짜·예산은 지어내지 않고 정해지지 않았다고 쓴다.
2. 글 전문을 먼저 쓴다. `yd-writer-kr` 로 쓰고 검사기를 통과시킨다. 그림에 넣을 수치와 날짜는 모두 이 글에 있어야 한다.
3. 장을 짠다. 아래 "장 순서"를 따른다. 보고서 목차(개요, 배경, 내용, 일정)를 그대로 쓰지 않는다.
4. 그림을 고른다. 아래 "그림 고르기" 표에서 장마다 하나를 고른다.
5. `brief.json` 을 쓴다. 형식은 `references/brief-format.md`, 예제는 `assets/example/brief.json` 에 있다.
6. 조립한다. `python3 scripts/build_brief.py brief.json -o 문서.html`
7. 검사한다. `python3 scripts/check_brief.py 문서.html` 의 오류가 0건이 될 때까지 고친다.
8. 눈으로 본다. 브라우저로 열거나 헤드리스 크롬으로 화면을 찍어 글자 겹침과 잘림을 확인한다. 검사기는 겹침을 보지 못한다.
9. 보고한다. 아래 "보고할 때"를 따른다.

## 장 순서

| 순서 | 장 | 주인 그림 |
|---|---|---|
| 첫 화면 | 결론 한 문장과 핵심 숫자 3~4개 | 숫자 띠 |
| 1 | 왜 하는가 | 행별 대비 그림 |
| 2 | 전체 시스템 구성도 | 층별 구성도 |
| 3 | 한 건의 흐름 | 노선도식 흐름도 |
| 4 | 어디가 엇갈리나 | 문서별 비교, 두 값 잇기 |
| 5 | 이미 가진 것 | 칸 채우기 |
| 6 | 언제, 누가 | 일정 막대그림, 조직 |
| 7 | 결재 전에 정할 것 | 결정 카드 |
| 끝 | 글 전문 | 접어 둔다 |

- 전체 시스템 구성도가 핵심이다. 앞쪽 장에 둔다.
- 해당 내용이 없는 장은 뺀다. 문서끼리 엇갈리는 곳이 없으면 4장은 없다.
- 장 제목은 주장 문장으로 쓴다. "추진 일정" 대신 "다섯 과제가 16주에 겹쳐 달린다" 로 쓴다.
- 결론(h1)은 한 문장이나 두 문장이다. 기간과 정할 것의 수처럼 숫자를 넣는다.

## 그림 고르기

| 말하려는 것 | 그림 | `kind` |
|---|---|---|
| 무엇으로 이루어졌나 | 층별 전체 구성도 | `architecture` |
| 한 건이 어떤 순서로 지나가나 | 노선도식 흐름도 | `metro` |
| 지금과 앞으로가 얼마나 다른가 | 행별 대비 그림 | `compare_rows` |
| 언제 무엇을 하나 | 일정 막대그림 | `gantt` |
| 같은 항목에 값이 둘이다 | 두 값 잇기 | `dumbbell` |
| 문서마다 범위가 다르다 | 문서별 비교 | `docs`, `pairs` |
| 몇 개 중 몇 개가 있나 | 칸 채우기 | `waffle` |
| 무엇을 정해야 하나 | 결정 카드 | `decisions` |

그림별 자료 형식과 작성 요령은 `references/figures.md` 에 있다.

## 그림 규칙

- 기존 그림을 그대로 붙이지 않는다. 원자료에 구성도가 있어도 구성요소만 가져와 새로 그린다.
- 화면 캡처 이미지를 넣지 않는다. 그림은 SVG 로 직접 그린다.
- 원자료에 없는 연결이나 배치는 그림 아래 주석에 밝힌다.
- 문서끼리 말이 다른 곳과 정해야 하는 곳에는 경고색 표시를 붙이고, 그림 아래에 번호별로 푼다.
- 문서끼리 엇갈리는 구성요소도 먼저 그리고 표시한다. 범위가 정해지면 뺀다.
- SVG 글자는 11px 이상으로 쓴다.
- 이모지를 아이콘으로 쓰지 않는다.

## 색

색은 역할 다섯 가지로 쓴다. 바탕(`paper`), 먹(`ink`), 강조색(`accent`), 경고색(`signal`), 보조 글자(`muted`).

- 유채색은 강조색과 경고색 두 계열만 쓴다. 보라·청록·초록·노랑을 함께 쓰지 않는다.
- 강조색은 주인공에 쓴다. 본선, 우리가 만드는 것, 바꾼 뒤의 모습이다.
- 경고색은 문서끼리 안 맞는 곳과 정해야 하는 것에만 쓴다.
- 나머지는 먹과 회색이다. 지금 있는 것과 범위 밖은 회색으로 흐리게 둔다.
- 상자는 가는 선과 여백으로 나눈다. 둥근 카드와 알약 딱지를 줄인다.

팔레트는 `assets/palettes.json` 에 세 벌 있다. 고르는 기준과 새 팔레트를 만드는 법은 `references/palettes.md` 에 있다.

| 이름 | 느낌 |
|---|---|
| `ink-cobalt` | 차분하고 또렷하다. 기술·금융 문서의 기본값 |
| `forest-terracotta` | 따뜻하고 안정적이다. 운영·조직·교육 문서 |
| `sea-coral` | 밝고 가볍다. 서비스·제품 소개 문서 |

## 검사 — `scripts/check_brief.py`

```bash
python3 scripts/check_brief.py 문서.html     # 문서 한 편
python3 scripts/check_brief.py --palettes    # 팔레트 전부
```

| 검사 | 수준 | 기준 |
|---|---|---|
| 색 대비 | 오류 | 본문 글자 7 이상, 보조 글자와 강조색 4.5 이상, 경고색 3 이상 |
| 색 구별 | 오류 | 강조색과 경고색의 색상 차 60도 이상 |
| 색 가짓수 | 오류 | 강조색·경고색 계열이 아닌 유채색이 없다 |
| 글자 크기 | 오류 | SVG 글자 11px 이상 |
| 이모지 | 오류 | 없다 |
| 캡처 이미지 | 오류 | png·jpg 이미지가 없다 |
| 구성도 | 오류 | 전체 구성도가 있다 |
| 결론 | 오류 | h1 이 하나다 |
| 그림 수 | 경고 | 그림 3개 이상 |
| 글 전문 | 경고 | 접어 둔 전문이 있다 |
| 외부 자원 | 경고 | 외부 주소를 불러오지 않는다 |

종료 코드는 오류가 없으면 0, 있으면 1, 사용법이나 파일 문제면 2 다.

## 보고할 때

- 결과 파일을 사용자가 바로 열 수 있게 넘긴다. 로컬이면 브라우저에 띄운다.
- 판단해서 넣은 것을 따로 밝힌다. 원자료에 없는 배치, 직접 센 수, 추정한 연결이 여기에 든다.
- 그림의 수치가 원자료와 맞는지 대조했는지 말한다. 대조하지 않았으면 하지 않았다고 쓴다.
- 내부 자료로 만든 문서는 공개 저장소나 공개 주소에 올리지 않는다.

## 폐쇄망

틀(`assets/template.html`)은 외부 자원을 불러오지 않는다. 글꼴은 Pretendard 가 설치돼 있으면 쓰고 없으면 시스템 글꼴로 보인다.
